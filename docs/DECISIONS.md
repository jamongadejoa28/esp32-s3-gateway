## A (Modbus) — 2026-10-19

- **A: engine split for host tests.** `components/mex150/mex_core.[ch]` (private header, pure C, listed in `GW_HOST_SOURCES_MEX150`) implements everything of `service.h` except FreeRTOS/UART: transaction (monitor `exchange()`), poll cycle, COMM state machine, write queue/verify, command history, reconfiguration, round-robin. I/O, clocks, locking and event delivery are injected (`mex_core_io_t`). `service.c` binds it to one mutex, the `mex_poll` task, TWDT, `GW_HB_MEX` and gw_evt; `uart_port.c` (`mex_uart.h`, private) owns UART1. `tests/test_mex_core.py` drives the engine with a simulated MEX150 bus.
- **A: enqueue freshness vs. long poll periods.** The check at enqueue accepts a snapshot younger than `MEX_FRESH_MS` OR an ONLINE device whose last cycle succeeded; otherwise `poll_ms` > 3000 (configurable up to 60 s) would reject every write as `offline`. The authoritative check right before sending always needs fresh data: the published snapshot (< 3 s) or the whole fast group re-read in the same cycle (the write is then sent after the fast group). Re-validation before send uses the published snapshot + this cycle's data + read-backs of earlier writes, so a queued `[run=1, hi_temp=30.0]` rejects the second one with `running_interlock`.
- **A: write execution points** are before every block and once after the last block (writes arriving mid-cycle run in the same cycle); at most 8 writes per cycle. After a write the slow group is (re-)appended so the post-write snapshot is complete, and the read-back word is stored into that snapshot. A queued write starts its device's cycle immediately (ahead of round-robin). A failed cycle rejects that device's still-queued writes with `offline` (cmd > 0).
- **A: write outcome** (monitor semantics): FC06 exception -> REJECTED `exception:N` (not retried; read-back still done for `raw_after`); read-back satisfies `mex_reg_write_matches()` -> APPLIED even if the FC06 answer was lost; else UNCERTAIN with `no_ack` (FC06 had no valid answer after retries) or `verify_mismatch`. `raw_after` without a read-back = the post-write snapshot's raw (or the pre-write raw if the cycle failed).
- **A: queue depth 8 counts a command until its final state** (queued + sent awaiting the post-write snapshot); a 9th is `busy` (cmd 0, ESP_ERR_NO_MEM). History keeps 16 records; pending records are never evicted (oldest final record is replaced).
- **A: COMM / snapshot.** `snapshot.online` becomes true at the first successful cycle and false only at the offline transition (cycles that fail below `offline_after` keep it; `mex_fresh()` covers staleness). `offline_count` counts every entry into OFFLINE, including the first decision at boot. `slow_valid` is reset at the offline transition and on a slave change ("since online"); the first cycle after (re)connecting always reads the slow group. An offline probe that answers continues the same cycle with the full plan (fast + slow), so recovery takes one cycle. UNKNOWN devices are polled with the full plan every `poll_ms`; OFFLINE ones with block `{1,0,8}` every 2 s. Reconfigure: slave change zeroes regs/coils/times (seq kept); an enable toggle only marks offline; name/timing changes reset nothing; UART line settings are re-applied only if baud/parity/stop changed.
- **A: counters.** `tx` = requests put on the wire (incl. retries; a failed UART write is not tx), `rx_ok` = valid non-exception answers, `exception`, `timeout` = no byte (or a UART read error after sending), `crc` = CRC mismatch incl. truncated frames, `malformed` = valid CRC but wrong unit/fc/length/echo; so `tx == rx_ok+crc+timeout+exception+malformed`. RTT = request start -> last byte of a valid answer (exceptions included), EWMA 1/8. Stats reset keeps `online_since_ms`.
- **A: local echo.** An exact echo of an FC01/FC03 request (transceiver without echo suppression) is skipped before parsing (unambiguous: a real read answer's byte count is never 0). An FC06 echo is indistinguishable from its ack; the read-back decides the outcome (HW_TEST).
- **A: misc.** UART RX FIFO timeout 3 symbols, RX ring 1 KB, TX unbuffered; the idle gap is a task delay followed by an input flush. `mex_service_start()` also returns UART driver errors as-is (e.g. ESP_FAIL) besides the documented codes. `mex_service_write()` from the `mex_poll` task itself returns ESP_ERR_INVALID_STATE (it would wait on its own queue). The poll task idles at most 500 ms between heartbeats and is woken by writes/reconfiguration.

## A (Modbus) — review fixes 2026-10-19 (supersede the matching A entries above)

- **A: total receive deadline.** IDF 6.1 `uart_read_bytes()` applies `ticks_to_wait` to every ring-buffer chunk (uart.c `while (length)` loop), so one multi-byte read on a trickling line (noise, babbling node, second master) could block for want × timeout and trip the TWDT. `mex_uart_read()` now goes through `mex_rx_bounded()` (mex_core.c, host-tested against a per-chunk driver model): buffered bytes are taken with 0 ticks, a blocking receive asks for exactly 1 byte with the remaining ticks, and the call returns at the deadline.
- **A: scheduler fairness.** A queued write moves its device ahead of round-robin only if the previous cycle was not itself write-triggered, or no other enabled device is due; so continuous write traffic delays every other device by at most one cycle each. After an OFFLINE probe, a due ONLINE/UNKNOWN device goes before the next probe. Offline probes are a single attempt (no retries; they repeat every 2 s anyway). With 3 dead peers the online device's poll gap is ≈ poll_ms at default timings and ≈ one cycle + one probe (≈ 3.5 s) at timeout 2000/gap 100 (was ≈ 27 s).
- **A: `raw_after` without a read-back = `raw_before`** (gw_events.h wording; was the post-write snapshot's raw). It also fits service.h's "else the last snapshot's raw" (the snapshot that validated the write).
- **A: enqueue freshness.** Strict DESIGN §9 rule (snapshot < 3 s) whenever `poll_ms` <= 3000 (default). Only with `poll_ms` > 3000 is an ONLINE device whose last cycle succeeded accepted with a snapshot younger than `poll_ms + 3000`; the check before sending stays strict (see Contract issues).

## C (web backend + auth) — review fixes 2026-10-19 (supersede the matching C entries above)

- **C: two async lanes, admission before begin.** WEB_RF_SLOW routes run on two workers (each prio 5, stack 6144, core 0, ≤ 4 admitted jobs): `httpd_login` for public slow routes (POST /auth/login: PBKDF2 + the global 1 s delay) and `httpd_async` for authenticated ones (password change, user create/update, factory reset, PUT /config/snmp, test trap, register write, run/stop). An unauthenticated login flood can no longer delay or 503 operator writes. Admission (`inflight < 4`) is decided on the httpd task BEFORE `httpd_req_async_handler_begin()`; the httpd task never calls `httpd_req_async_handler_complete()` (in IDF 6.1 it waits with portMAX_DELAY for a control-mailbox slot that only the httpd task frees, which was a self-deadlock). Busy lane → 503 `busy`.
- **C: control-mailbox budget.** httpd's control mailbox has CONFIG_LWIP_UDP_RECVMBOX_SIZE (8) slots. WS frames in flight are capped at 8 − 3 = 5 (`WS_FRAME_POOL` stays 8), so the heartbeat, async completions and session closes always find a slot.
- **C: closing connections.** On the httpd task a handler that fails after responding, or a RAW_BODY handler that refuses, makes the router return ESP_FAIL: httpd deletes the session synchronously, with no mailbox slot and no drain of an unread upload body. This includes every OTA refusal (400/413/422/423/500/503). The async worker half-closes (`shutdown(SHUT_WR)`) before completing. `web_close_fd()` (WS drops, allowlist re-check) uses `httpd_sess_trigger_close()` and falls back to `shutdown(SHUT_WR)` when the mailbox is full. Trade-off: closing with unread upload data may reset the connection before the client reads the 4xx.
- **C: IP allowlist after a change.** It is also checked per request in the router and in the WS pre-handshake: an excluded peer is closed without an answer. One SYS_TICK after CONFIG_CHANGED{SECURITY}, by which time net has installed the new filter, an httpd work item closes every open socket the filter no longer admits; WS clients get `bye` `revoked`. `on_open` refusals no longer double-close the fd (IDF's accept path closes it).
- **C: config import lock-out guard.** POST /system/config/import refuses an `ip_allow` that would exclude the requester (422 `validation`, field `security.ip_allow`, code `lockout`), the same rule as PUT /config/security.
- **C: SNMP secrets and config as one unit.** PUT /config/snmp and config import take a web-local leaf lock around the SNMP-related secrets and the config commit, with a 3 s wait and 503 `busy` on timeout. Inside the lock:
  1. PUT /config/snmp answers 409 `conflict` if the SNMP section changed since it was parsed. Import recomputes the trap-community remap from the section current under the lock.
  2. `cfg_snmp_check_secrets` runs.
  3. `secrets_modify` saves the previous RO/RW/v3/trap communities.
  4. `cfg_commit`/`cfg_commit_all` runs. If it fails, a second `secrets_modify` restores the saved values.
  PUT /config/snmp now checks in this order: parse → `cfg_validate_with` → v3 passphrases + key localization (outside the lock) → the lock steps above.
- **C: rate limiter never evicts a locked slot.** LRU replacement takes only free or unlocked slots. While all 16 slots are locked, an IP without a slot is treated as locked until the earliest slot lock ends (`auth_rl_check`), and its failures allocate nothing. Rotating through more than 16 addresses no longer resets locks or their doubling. The availability cost: during such an attack, new LAN addresses cannot log in for up to the shortest active lock (≤ 30 min). The recovery AP stays reachable but shares this limiter.
- **C: /meta/alarms caching.** `ETag: "<elf-sha 12>-a<FNV-1a32 of the effective severities>"`, `Cache-Control: no-cache`, If-None-Match → 304. The body depends on `sev_override`, so a pure build-id ETag would be wrong.
- **C: 409 range body.** `{"value"}` not representable at the register scale answers exactly `{"error":"rejected","state":"rejected","cmd":0,"addr":…,"reason":"range"}`, with no `message`, per the write-result schema.
- **C: ws_hub targeted bye** carries the session id: a `bye` queued for fd N of session S is not delivered if fd N was reused by another session's client meanwhile.

## B (store + alarm) — review fixes 2026-10-19 (supersede the matching B entries above)
